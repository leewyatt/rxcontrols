RXImageView

Style class: rx-image-view

The RXImageView control extends Region and has all the properties of Region; it has no public substructure.

Css Property Values Default
-rx-image-fit cover, contain, stretch cover
-rx-image-insets size | size size | size size size size 0
-rx-image-radius size 0

-rx-image-fit controls cover, contain, or stretch rendering. -rx-image-insets changes the image allocation area relative to the Region content area; negative values expand the drawn image without changing layout size. -rx-image-radius rounds the actual rendered image area with a fixed pixel radius.

RXClipPathImageView

Style class: rx-clip-path-image-view

The RXClipPathImageView control extends Region and has all the properties of Region; it has no public substructure.

Css Property Values Default
-rx-clip-svg String (SVG path in 0-100 coordinate space) null

Clipping is supplied via -rx-clip-svg in CSS or setClipSvg(String) in Java. Predefined SVG path strings are exposed as constants on RXClipPathImageView (e.g. SHAPE_CIRCLE, SHAPE_HEXAGON, SHAPE_SHIELD). The image is cover-fit scaled to fill the control bounds; overflow is cropped. When the image is null, fails to load, or its metadata is not yet parsed, the control renders nothing.

RXPasswordField

Style class: rx-password-field

A password-entry control that extends JavaFX PasswordField and adds left and right slots for user-supplied nodes (typically a reveal toggle on the right). It does not bundle any built-in buttons — set left / right with any Node, and bind your toggle's selected state to showPasswordProperty() to switch between masked and plain text.

Substructure

.rx-password-field — extends PasswordField
  .left-wrapper — StackPane (present only when left is set)
  .right-wrapper — StackPane (present only when right is set)

Pseudo-classes

CSS Pseudo-class Comments
showing applies when showPassword is true; CSS hook for adjusting the reveal-toggle's visual
has-left-node applies when the left property is non-null
has-right-node applies when the right property is non-null
has-no-side-nodes applies when both left and right are null (mutually exclusive with the two above)

CSS Properties

Css Property Values Default
-rx-echo-char Character (single-quoted string literal; first character is used) '●' (●)
-rx-text-padding Insets 0 (UA stylesheet sets 0.583em horizontally when :has-left-node / :has-right-node is active)

Padding model. Identical to RXTextField — see that section for the three-layer breakdown (-fx-padding vs. -rx-text-padding vs. .left-wrapper / .right-wrapper internal padding).

Accessibility. Inherits PasswordField's defaults — AccessibleRole.PASSWORD_FIELD, screen readers receive the prompt text rather than the password, and cut() / copy() are no-ops. These behaviors stay in effect even while showPassword is true.

RXTextField

Style class: rx-text-field

A base text-field control that adds left and right slots for user-supplied nodes. It does not bundle any built-in buttons or actions — set left / right with any Node (Label, Button, HBox, etc.).

Substructure

.rx-text-field — extends TextField
  .left-wrapper — StackPane (present only when left is set)
  .right-wrapper — StackPane (present only when right is set)

Pseudo-classes

CSS Pseudo-class Comments
has-left-node applies when the left property is non-null (independent of the node's visible / opacity / managed state)
has-right-node applies when the right property is non-null (independent of the node's visible / opacity / managed state)
has-no-side-nodes applies when both left and right are null (mutually exclusive with the two above)

CSS Properties

Css Property Values Default
-rx-text-padding Insets 0 (UA stylesheet sets 0.583em horizontally when :has-left-node / :has-right-node is active)

Padding model. RXTextField has three independent padding concepts:

  • -fx-padding (inherited from Region) sizes the control's outer dimensions and gives the text vertical breathing room. When no side node is present it also gives horizontal padding between the text and the outer border; when a side node is present it does NOT control the wrapper-to-text gap.
  • -rx-text-padding is the inner padding of the text editor region, applied after the left / right wrapper widths are excluded. Horizontal values are the exact gap between a present wrapper and the text. Vertical values add inner padding to the text region and participate in min/pref height (enlarging vertical textPadding increases the control's preferred height so the text is not clipped).
  • .left-wrapper / .right-wrapper accept their own -fx-padding (StackPane API) for internal breathing around the child node — independent of -rx-text-padding.

Note: The user-agent stylesheet provides differential -rx-text-padding defaults via :has-left-node / :has-right-node. If you override -rx-text-padding in an author stylesheet without using these pseudo-classes, the UA defaults no longer apply.
