Global Color Tokens

RxControls ships a looked-up color role layer declared on every control root in the user-agent stylesheet (rx-controls.css). Every control — and its descendants, via the looked-up walk-up — resolves the full set with zero setup. To retheme, override a token in an author stylesheet on the control root selector (a future RXTheme overlay does exactly this).

Three layers — do not confuse them:

  • Global color tokens (table below) — looked-up colors with role names (-rx-primary, -rx-on-surface, …). Defined on the control root, referenced from any descendant rule; this is the theming override point.
  • Component styleable properties — part names (-rx-fill, -rx-line-color, -rx-dot-fill, -rx-ripple-fill, …), documented per control. Their defaults now reference a role token; they remain the per-control override point.
  • Non-color (radius, spacing, elevation / shadow, state opacity, sizes) — not global tokens. JavaFX 17 resolves looked-up values only for colors, so these stay literal per component or remain component styleable Number / Insets properties.

AtlantaFX theme bridge

Apps built on AtlantaFX can make RxControls follow the host theme with AtlantaFXThemeBridge. It layers an author-origin stylesheet (rx-controls-atlantafx.css) that re-points the color role tokens above at AtlantaFX -color-* functional tokens. Install the AtlantaFX theme as the Application user-agent stylesheet before building the scene, then apply the bridge:

Application.setUserAgentStylesheet(new PrimerLight().getUserAgentStylesheet());
Scene scene = new Scene(root);
AtlantaFXThemeBridge.install(scene);   // popups opened afterwards follow it too

Apply at scene level (recommended) or to a single Parent subtree (install(Parent)) when mixing themes. A scene-level bridge reaches popups (e.g. RXCascader's) because the popup snapshots its owner scene's stylesheets at show time; a parent-level bridge reaches a popup only when that parent is on the owning control's ancestor chain.

Scope. The bridge re-points the color role tokens and, because AtlantaFX does not define the Modena -fx-* palette, also supplies the few Modena base colors RxControls rules still reference directly (-fx-control-inner-background, -fx-accent, -fx-text-base-color, …) mapped to -color-* — so controls not yet migrated to role tokens (e.g. the cascader) follow the theme too. Non-color values (radius, spacing, sizes) are not themed.

Built-in dark theme

For a built-in dark look (no external theme needed), RXTheme layers an author-origin overlay (rx-controls-dark.css) that re-defines the color role tokens with a self-contained dark palette and overrides the Modena -fx-* base colors, so the whole library — including controls still using raw -fx-* — turns dark:

RXTheme.install(scene, RXTheme.Variant.DARK);  // go dark (popups follow if opened afterwards)
RXTheme.install(scene, RXTheme.Variant.LIGHT); // back to the built-in light baseline
RXTheme.uninstall(scene);                      // also back to the baseline

Unlike the AtlantaFX bridge (which references a host theme's -color-*), the dark overlay uses literal dark values, so it works on the default Modena baseline. It also flips -rx-state-overlay-color to white (ripple / hover tint on dark).

RXTextView

Style class: rx-text-view

A non-editable, wrapping block of text the user can select and copy. There is no visible caret. Colours are control-level styleable properties written by the skin into the internal text / selection nodes; the substructure style classes are advanced hooks (font, effect) rather than the colour entry points, so set colours through the -rx-* properties below, e.g. .rx-text-view { -rx-selection-fill: #0078d7; -rx-selected-text-fill: white; }.

To inset the text, use control-level padding (.rx-text-view { -fx-padding: … } or setPadding(…)) — the simplest option. Padding set directly on the internal .text-flow is also honored: the selection background, the keyword highlight and mouse hit-testing all follow the TextFlow's insets.

Substructure

selection-shape — Path
text-flow — TextFlow
  plain — Text

Css Property Values Default
-rx-text-fill Paint #1b1f2a
-rx-selection-fill Paint rgba(0, 120, 215, 0.3)
-rx-selected-text-fill Paint #1b1f2a
-fx-text-alignment LEFT,CENTER,RIGHT,JUSTIFY LEFT
-fx-line-spacing double 0

-rx-selected-text-fill is the foreground of the selected glyphs; null means "do not override" (the glyphs keep -rx-text-fill), not transparent. It is applied through JavaFX Text.selectionFill, which only honours a plain colour reliably.

RXHighlightTextView

Style class: rx-highlight-text-view

Extends RXTextView, highlighting one or more keywords inside its text. Keywords (the keywords list) are matched literally or as regular expressions, case-sensitively or not, per the matchRules property; the read-only matched reports whether any keyword matched. Keyword highlighting only paints a background — it never changes the keyword text colour — so a long search result does not split the body into many nodes.

The RXImageView control extends Region and has all the properties of Region; it has no public substructure.

Css Property Values Default

RXMaterialTextField / RXMaterialPasswordField / Material number fields

Style classes: rx-material-text-field / rx-material-password-field

Material-style single-line inputs: a floating label, a bottom activation line with a focus (accent) line, a supporting (helper / error) row, and a built-in clear button. The password variant adds a reveal (eye) button, a runtime revealPassword toggle and an echoChar mask. The floating label falls back to promptText when labelText is blank (a blank promptText is likewise ignored); the native prompt node is suppressed via -fx-prompt-text-fill: transparent.

Number variants. RXMaterialDecimalField (BigDecimal), RXMaterialDoubleField, RXMaterialIntegerField and RXMaterialLongField extend RXMaterialTextField and inherit the pseudo-class and CSS-property set below unchanged — they declare no additional CSS properties (-rx-echo-char stays password-only). Each variant keeps the inherited rx-material-text-field style class and adds the shared family class rx-material-number-field plus its own class: rx-material-decimal-field, rx-material-double-field, rx-material-integer-field, rx-material-long-field.

RXTextField

Style class: rx-text-field

A base text-field control that adds leading and trailing slots for user-supplied nodes. It does not bundle any built-in buttons or actions — set leading / trailing with any Node (Label, Button, HBox, etc.).

Substructure

.rx-text-field — extends TextField
  .leading-wrapper — StackPane (present only when leading is set)
  .trailing-wrapper — StackPane (present only when trailing is set)

Pseudo-classes

CSS Pseudo-class Comments
has-leading applies when the leading property is non-null (independent of the node's visible / opacity / managed state)
has-trailing applies when the trailing property is non-null (independent of the node's visible / opacity / managed state)
has-no-slots applies when both leading and trailing are null (mutually exclusive with the two above)

CSS Properties

Css Property Values Default
-rx-text-padding Insets 0 (UA stylesheet sets 0.583em horizontally when :has-leading / :has-trailing is active)

Padding model. RXTextField has three independent padding concepts:

  • -fx-padding (inherited from Region) sizes the control's outer dimensions and gives the text vertical breathing room. When no side node is present it also gives horizontal padding between the text and the outer border; when a side node is present it does NOT control the wrapper-to-text gap.
  • -rx-text-padding is the inner padding of the text editor region, applied after the left / right wrapper widths are excluded. Horizontal values are the exact gap between a present wrapper and the text. Vertical values add inner padding to the text region and participate in min/pref height (enlarging vertical textPadding increases the control's preferred height so the text is not clipped).
  • .leading-wrapper / .trailing-wrapper accept their own -fx-padding (StackPane API) for internal breathing around the child node — independent of -rx-text-padding.

Note: The user-agent stylesheet provides differential -rx-text-padding defaults via :has-leading / :has-trailing. If you override -rx-text-padding in an author stylesheet without using these pseudo-classes, the UA defaults no longer apply.

RXRadioToggleButton

Style class: rx-radio-toggle-button (also: rx-toggle-button, toggle-button)

RadioButton-like selection behaviour with plain ToggleButton appearance (no radio dot). Extends RXToggleButton, inheriting all of its ripple properties (see the table above) and CSS.
